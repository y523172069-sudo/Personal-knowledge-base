## 图片 1：智能 AI Agent 系统架构全景图

这张图展示的是 AI 风控官从用户入口到 Agent 执行、数据支撑的整体分层架构。

### 分层识别

| 层级 | 图中名称 | 作用理解 |
| --- | --- | --- |
| 用户交互层 | 官网入口 | 系统最前端，作为用户接入服务的唯一官方入口 |
| 平台服务层 | 对接请求 | 接收用户输入，并将请求传递到后端核心逻辑层 |
| 智能体层 | 意图识别与执行 | 由 Agent 负责理解用户问题、判断决策路径，并调用 MCP 或 RAG 完成检索和生成 |
| 数据支撑层 | 底层驱动 | 为上层 AI Agent 提供持续、稳定的原始数据支持 |

### 智能体层内部结构

| 模块 | 作用理解 |
| --- | --- |
| 千问 Agent 逻辑 | 核心大脑，包含提示词、决策路径、MCP 调用以及 RAG 检索增强生成 |
| 决策路径 | 判断当前问题应该走知识检索、工具调用，还是组合链路 |
| MCP（KYC 与风险查询） | 面向业务工具或能力调用，支撑 KYC 与风险查询相关操作 |
| RAG | 检索增强生成，用于结合知识库内容生成更可靠的回答 |

### 初步理解

AI 风控官不是单纯的大模型问答，而是由“前端入口 + 平台服务 + Agent 决策 + MCP 工具调用 + RAG 检索 + 底层数据”组成的业务型 AI Agent 系统。Agent 的关键价值不只是生成答案，而是判断问题意图、选择调用路径，并把知识、工具和数据整合成可返回给用户的结果。

## 图片 2：AI 风控官调用链路序列图

这张图展示的是用户提问后，系统内部各模块之间的调用顺序。

### 参与角色

| 角色 | 作用理解 |
| --- | --- |
| 用户端（主站入口 / adminn 内测版） | 用户发起问题和接收答案的入口 |
| Java 服务 | 承接用户请求，并负责和 Agent 之间传递问题与答案 |
| Agent | 核心编排模块，负责问题传输、知识检索、工具调用、答案整合 |
| 知识库 / 向量数据库 | 支撑知识检索阶段，返回相关检索结果 |
| 黑盒（MCP 客户端 - MCP 服务器） | 提供工具列表与工具调用能力 |
| 大模型（千问-3.5plus） | 负责回答生成、工具选择和基于数据的最终回答生成 |

### 阶段识别

| 阶段 | 调用链路 | 作用理解 |
| --- | --- | --- |
| 用户提问 | 用户端 → Java 服务 → Agent | 用户问题进入系统，Java 服务将问题传递给 Agent |
| 知识检索阶段 | Agent → 知识库 / 向量数据库 → Agent | Agent 发送检索请求，知识库返回检索结果 |
| 初始回答生成 | Agent → 大模型 → Agent → Java 服务 → 用户端 | 大模型基于问题和检索结果生成回答，并通过 Java 服务返回用户端 |
| 工具调用阶段 | Agent → MCP 黑盒 → Agent；Agent → 大模型 → Agent | Agent 先获取工具列表，再请求大模型选择工具并返回调用参数 |
| 数据获取与最终答案 | Agent / Java 服务 → API / 数据服务 → Agent → 大模型 → Agent → Java 服务 → 用户端 | 系统获取业务数据后，再由大模型基于数据生成最终答案并返回 |

### 初步理解

这张序列图说明 AI 风控官的回答过程可能存在两类路径：

1. 只依赖知识检索和大模型生成的普通问答路径；
2. 需要调用工具、获取业务数据后再生成答案的增强路径。

研发轮岗中需要重点观察：哪些问题只需要 RAG，哪些问题必须调用 MCP 工具；工具参数如何被选择；业务数据如何进入最终回答；以及错误答案如何被定位到知识库、工具调用、数据接口或大模型生成环节。

## 后续可跟进问题

| 方向 | 待观察问题 |
| --- | --- |
| 问题分类 | 用户问题如何被识别为普通问答、风险查询、KYC 查询或需要人工介入的场景？ |
| RAG | 哪些回答依赖知识库 / 向量数据库？知识库内容如何维护和更新？ |
| MCP | MCP 工具列表由谁定义？工具参数如何生成和校验？ |
| 数据 | 哪些数据是实时获取，哪些来自知识库或历史沉淀？ |
| 准确性 | AI 输出错误时，如何判断问题出在检索、工具、数据还是大模型生成？ |
| 反馈闭环 | 此前内部使用调研中的高频问题，能否映射到当前系统架构中的具体环节？ |
| 风控边界 | 哪些风险判断可以由 AI 辅助，哪些必须保留人工审核或风控标准话术？ |
