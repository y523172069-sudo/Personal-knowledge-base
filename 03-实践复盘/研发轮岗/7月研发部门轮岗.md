## 1. 项目名称修正

7 月轮岗的项目名称统一为：

> 7月研发部门轮岗

AI 风控官不是项目名称，而是当前轮岗中已经识别出的主要学习和协作主线。

本轮暂不新增其他独立项目沉淀；后续新增内容需先确认是否属于 7 月研发部门轮岗范围。

## 2. 当前主线：AI 风控官 / 内部 AI 助手

这条主线承接产品设计部门轮岗期间已经完成的 AI 风控官内部使用分析，在研发部门轮岗阶段进一步进入系统链路和研发协作理解。

当前已沉淀材料包括：

- AI Agent 系统架构图；
- Agent 调用链路序列图；
- AI 助手内部优化与外部调研会议记录；
- 产品轮岗阶段的 AI 风控官内部使用数据分析与会议纪要。

当前重点理解的问题：

- Agent、RAG、MCP、知识库 / 向量数据库、数据调用链路分别承担什么作用；
- 模型幻觉、模糊查询、多轮上下文丢失等问题如何影响内部用户体验；
- 内部使用反馈如何转化为研发优化、运营推广和外部客户调研计划；
- 面向客户的外部调研如何验证真实风控需求。

## 3. 沉淀链路

```text
产品轮岗：AI 风控官内部使用数据分析 / 会议纪要
        ↓
研发轮岗：理解 Agent / RAG / MCP / 数据调用链路
        ↓
会议记录：模型幻觉、模糊查询、多轮上下文、内部运营、外部调研
        ↓
后续补充：问题复现、开发协作、测试验收、问卷和调研回收结果
```

当前这条链路更适合记录为“学习与沉淀”，而不是直接包装成项目落地成果。

## 4. 当前可以证明什么

可以证明：

- 已经开始从产品视角理解 AI Agent 系统架构；
- 能把用户体验问题和底层链路联系起来，例如模型幻觉、模糊查询、多轮上下文与知识检索 / 数据调用之间的关系；
- 能把会议记录整理成后续运营推广和外部调研待办；
- 能将产品轮岗的 AI 使用分析延伸到研发轮岗的技术链路学习。

当前不能写成：

- 独立完成 AI 风控官研发；
- 独立负责 AI Agent 产品落地；
- 已解决模型幻觉或模糊查询问题；
- 已形成上线结果、业务指标或客户验证结果。
