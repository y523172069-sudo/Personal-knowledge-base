# 钱包美金入账链路

## 为什么学

- 领导安排本人自学即将开始的钱包项目，重点是美金跨境支付场景。
- 目标：能和产品经理、运营、资深研发就真实的实现问题对上话。
- 本人当时没有技术背景，处在学习阶段，还没有独立负责或开发系统。

## 学了什么

| 主题 | 内容 |
| --- | --- |
| 美金电汇和人民币支付的区别 | 银行电汇没有回调机制，必须主动对账 |
| 三个独立流程 | 下单、银行流水入库、资金匹配 |
| 表设计 | 订单、付款链接、银行流水、账户、账本流水 |
| 收款账户路由 | 用规则表 + 兜底策略决定走哪个收款账户 |
| 自动对账 | 付款人名称标准化 + 相似度打分 |
| 并发重复入账 | 四层防御：唯一索引、条件更新、悲观锁、分布式锁 |
| 状态机 | 四个实体：`pay_order`、`pay_link`、`payment`、`bank_transaction` |

## 记下的原则

- 金额用整数存最小单位，不用浮点数。
- 不信任前端传来的值，所有金额计算在服务端做。
- 幂等靠数据库唯一索引保证，而不是应用层的 if 判断。
- 会随时间变化的值，要在交易发生时存一份快照。
- 历史账本记录不修改，更正只能通过新增冲正记录（红冲）。
- 美金电汇靠主动对账，而不是像人民币那样靠回调。

## 自测与补漏

- 自测时较弱的两块：悲观锁和唯一索引的区别；用户操作后订单与付款的状态流转。
- 两块都用具体的代码实验和追问重新过了一遍。
