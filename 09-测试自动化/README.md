## 4. 脚本审计机制（已定）

### 4.1 流程

两段式审计（2026-09-28 定）：

```
AI 生成脚本
  → 【运行前 · 快审】至少搞清楚：会读写哪些文件、会不会操作真实环境
  → 运行验证
  → 【运行后 · 全审】逐段阅读 → 填审计记录 → （可选）修改/重写 → 再运行
  → 归档
```

已定：

- [x] 审计时机：两段式（运行前快审 + 运行后全审）
- [x] 快审通过即可运行；全审在运行后完成
- [x] AI 交付脚本时须附带（2026-09-28 定）：
  - 代码内逐段注释
  - 单独的「快审摘要」：读写哪些文件、访问哪些地址、有没有登录态 / 删除 / 提交类操作
- [x] 快审检查项保持现状：读写哪些文件、访问哪些地址、有没有登录态 / 删除 / 提交类操作，不再增加（2026-09-28）

### 4.2 单个脚本审计记录的字段

| 字段 | 说明 |
|---|---|
| 脚本名 / 路径 | |
| 生成来源 | 哪个工具、哪次对话、哪天 |
| 作用 | 一句话，由本人写 |
| 输入 / 输出 | 读什么文件、产出什么文件；由本人填写，用于核对 AI 快审摘要 |
| 用到的知识点 | 关联到 02-工具栈学习 里的哪些条目 |
| 没看懂的地方 | 待追问的问题 |
| 本人改动 | 改了什么、为什么 |
| 风险点 | 如账号/登录态、写文件、删文件、真实环境操作；由本人填写，用于核对 AI 快审摘要 |
| 审计结论 | 由本人三选一：通过 / 通过但有疑问 / 不通过需重写 |

已定：

- [x] 不设「逐段解读」栏（逐段说明由 AI 注释承担），保留「没看懂的地方」和「本人改动」（2026-09-28）
- [x] 「输入 / 输出」「风险点」保留，由本人自己填，用来核对 AI 快审摘要是否准确（2026-09-28）
- [x] 「审计结论」用固定状态：通过 / 通过但有疑问 / 不通过需重写（2026-09-28）

- [x] 其余字段（脚本名 / 路径、生成来源、作用、用到的知识点）保持不改（2026-09-28）
