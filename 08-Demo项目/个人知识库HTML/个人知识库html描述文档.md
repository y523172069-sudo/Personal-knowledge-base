## 项目定位

这是一个本地静态 HTML Demo，用于把管培生个人知识库整理成可交互页面。

项目不依赖后端服务、构建工具或外部网络资源。正常情况下，直接用浏览器打开 HTML 文件即可预览。

## 当前文件结构

- `index.html`：求职版入口。
- `app.js`：求职版交互和数据。
- `internal.html`：内部汇报版入口。
- `internal-app.js`：内部汇报版交互和数据。
- `styles.css`：两个入口共用样式。
- `README.md`：项目现有说明。
- `提交包/`：用于存放可提交的本地交付文件。

## 两个入口的区别

`index.html` 是求职版，可以包含简历素材、Demo 选题、面试复盘和求职相关视角。

`internal.html` 是内部汇报版，面向公司内部阶段汇报，只展示轮岗学习沉淀、项目案例、能力地图、证据索引、个人学习心得和思考汇总。

除非用户明确要求，不要修改 `index.html` 和 `app.js`。

## 内部汇报版维护口径

内部汇报版后续按照当前 `internal.html` / `internal-app.js` 版本迭代维护。

重点不是证明业务结果或交付闭环，而是展示轮岗期间的学习、共创和沉淀。

不要把材料缺口作为页面重点。材料缺口只在后台知识库维护，不放在领导汇报版主界面。

轮岗时间线固定口径：

- 3 月：人力行政与会议部门轮岗
- 4 月：销售部门轮岗
- 5 月：客户成功部门轮岗
- 6 月：产品与设计部门轮岗

项目案例取消证据 tag 展示，重点展示“共创 / 成长 / 思考”。

沉淀链路按时间顺序展示个人成长经历。

## 保密边界

- 页面只使用脱敏摘要。
- 不展示公司内部原始材料。
- 不展示客户、员工、工单截图、内部系统原始细节。
- 公司内部材料只能做概括性表达，不复制原始记录。
- 如果用户要求公开发布或外发，需要先询问是否继续做更彻底的脱敏和通用化改写。

## 内部汇报版禁用内容

`internal.html`、`internal-app.js` 和内部汇报提交版中，不应出现以下求职相关内容：

- 求职
- 简历
- 面试
- 作品集

如果确实需要表达类似含义，先问用户确认，再改成更中性的内部表达。

## 提交包规则

如果用户要“提交本地 HTML 文件”“作为产出提交”或类似需求，优先整理 `internal.html` 的提交版。

当前已采用过的提交方式：

- 将 `styles.css` 和 `internal-app.js` 内联进一个单文件 HTML。
- 单文件放在 `08-Demo项目/个人知识库HTML/提交包/`。
- 提交包内只放可提交 HTML 和说明文件。
- 如需压缩包，只压缩提交 HTML 和提交说明，不打包源文件或后台材料。

如果用户没有明确要求，不要重新设计交付形式，先沿用上述方式。

## 修改后的检查清单

每次修改后至少检查：

- HTML 引用是否存在。
- 页面内是否有重复 ID。
- `app.js` 和 `internal-app.js` 是否语法正常。
- 内部汇报版是否包含禁用内容。
- 如果更新了内部汇报版源文件，提交包里的单文件 HTML 是否需要同步重建。
- 压缩包如被重建，确认里面只包含用户确认过的提交文件。
