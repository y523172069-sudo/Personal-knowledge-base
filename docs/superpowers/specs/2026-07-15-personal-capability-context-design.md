# 个人能力长期上下文与证据准入设计

- 状态：待用户复核
- 创建日期：2026-07-15
- 保密级别：已脱敏
适用范围：个人知识库中的能力认定、简历、述职、面试材料、作品集和 Demo

## 1. 背景与目标

用户提供了《姚远｜个人能力边界与建模能力说明》，希望将其作为 Codex 项目的长期上下文，并要求后续所有新增能力都必须附带对应项目证据。

该文档被定义为“阶段性能力基线”：它用于约束能力表述、明确当前边界和指导后续沉淀，但不直接替代项目证据，也不因写入该文档就自动成为已验证能力。

本次建设目标是形成以下闭环：

```text
项目事实与产出
→ 项目复盘
→ 证据编号（E-XXX）
→ 证据索引
→ 能力地图
→ 简历 / 述职 / 面试 / Demo
```

## 2. 采用方案

采用“根目录 Codex 规则 + 独立能力基线文件 + 治理与模板约束”的组合方式。

不把完整能力说明直接写入根目录规则文件，避免长期上下文过长、重复维护和内容漂移。根目录规则只保存必须执行的约束，并链接到人可读的能力基线与治理规则。

## 3. 文件设计

### 3.1 根目录 `AGENTS.md`

新增根目录 `AGENTS.md`，作为 Codex 在本项目中的持续执行约束。主要包含：

1. 处理能力地图、简历、述职、面试材料、作品集或 Demo 前，读取能力基线和知识库治理规则；
2. 新增能力必须附带项目证据，不接受只有自我评价的能力升级；
3. 新增能力默认按“候选能力”处理，只有建立项目复盘和 E 编号后才能进入正式能力地图；
4. 缺少证据时必须标记为“待验证”，不得自行补充结果；
5. 不将团队成果全部归因于个人，不将“提供依据”改写为“独立落地”，不将“通过审核”改写为“已上线”；
6. 对外资产必须遵守脱敏和仅本地材料边界。

### 3.2 `04-能力证据/个人能力边界与建模能力说明.md`

保存用户提供的完整原文，并在文件顶部增加治理元数据和使用边界：

- 状态：进行中；
- 定位：阶段性能力基线；
- 证据属性：该文件不是项目证据；
- 更新条件：新增能力必须关联项目复盘和 E 编号；
- 降级规则：证据不足时写入候选能力或待验证区域。

原文主体保持完整，不因本次纳入而重写个人定位。

### 3.3 `00-导航/知识库治理规则.md`

治理规则升级一个次版本，新增“能力认定与证据准入”章节，明确：

| 状态 | 最低要求 | 允许进入的位置 |
| --- | --- | --- |
| 能力线索 | 自我观察或单次表现 | 收集箱、复盘中的待验证判断 |
| 能力候选 | 至少一个具体项目和个人动作 | 能力基线的待验证部分、待补证据清单 |
| 已有能力证据 | 项目复盘 + E 编号 + 可说明的材料或反馈 | 能力地图 |
| 对外能力表述 | 已有能力证据 + 贡献边界 + 脱敏复核 | 简历、述职、面试、Demo |

能力等级提升需要新增证据或跨项目复用记录，不能只依据措辞优化或个人主观判断。

### 3.4 模板

更新以下模板：

- `06-模板/项目案例模板.md`
- `06-模板/工作复盘模板.md`

增加或强化以下字段：

模板只约束后续新建或实质更新的内容，不批量改写历史文档。

### 3.5 导航入口

在根目录 `README.md` 和 `04-能力证据/能力地图.md` 中增加能力基线入口，保持现有 Codex 链接兼容规则。

能力基线本身不创建 E 编号，因为它属于总结与约束，不是原始项目证据。

## 4. 能力新增流程

后续发现新能力时按以下顺序处理：

1. 记录能力线索以及发生场景；
2. 指向一个具体项目或任务；
3. 明确个人职责、关键动作、交付物和结果边界；
4. 将项目整理为实践复盘；
5. 在证据索引中建立或关联 E 编号；
6. 判断证据强度和主要限制；
7. 再决定是否更新能力地图；
8. 只有通过脱敏与贡献边界检查后，才允许转入对外资产。

如果第 2 至第 5 步无法完成，该内容只能保留为“待验证”，不能写成确定能力。

## 5. 既有内容处理边界

本次不对现有 E-001 至 E-013 进行全面重评，也不批量调整能力等级。

能力说明中已经出现的项目、数据和结果继续沿用现有证据索引的限制口径。若能力说明与证据索引发生冲突，以当前任务要求、治理规则和证据索引中的可验证事实为准。

发现缺少证据的已有能力表述时，只登记到待补证据清单，不为保持文档完整而虚构材料。

## 6. 验证标准

实施完成后必须满足：

1. 根目录存在可被 Codex 读取的 `AGENTS.md`；
2. 能力基线文件完整保存用户原文，并明确“不是项目证据”；
3. 治理规则包含新增能力的准入和降级机制；
4. 两个模板均包含项目证据、贡献边界和验证状态字段；
5. 能力基线至少有一个稳定导航入口；
6. 所有新增本地 Markdown 链接可解析；
7. 没有把仅本地原始材料或内部敏感信息新增到公开仓库；
8. Git 变更只涉及本设计范围内的文件。

## 7. 非目标

本次不包含：

- 重写个人简历；
- 调整现有 Demo 页面；
- 批量重评全部历史能力；
- 为能力说明中的每一句话新增证据编号；
- 上传仅本地原始材料；
- 将待验证项目包装成已完成成果。
