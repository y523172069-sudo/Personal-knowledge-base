# 云端同步使用说明

状态：进行中
创建日期：2026-07-06
适用仓库：`https://github.com/y523172069-sudo/Personal-knowledge-base.git`

## 1. 同步原则

本知识库采用“Git 私有仓库同步主体内容，原始材料仅本地保存”的方式。

可以同步到 GitHub 的内容：

- Markdown 笔记；
- 知识库目录结构；
- 脱敏后的实践复盘；
- 证据索引、能力地图、简历素材池、Demo 选题池；
- HTML Demo 源文件；
- 可重新生成的提交包 HTML。

不进入 GitHub 的内容：

- 公司内部 Excel、Word、PPT 原件；
- Jira 截图、企业微信截图、内部系统截图；
- AI 风控官原始数据、会议纪要原文、客户名单；
- `04-能力证据/原始材料-仅本地/`；
- `01-收集箱/待整理原始材料/`；
- `.codex/`、`.tmp/`、`.agents/`；
- 可重新生成的 `.zip` 文件。

## 2. 第一次在另一台电脑下载知识库

在新电脑上打开 PowerShell，进入希望保存知识库的位置，例如：

```powershell
cd C:\Users\你的用户名\Documents
```

克隆仓库：

```powershell
git clone https://github.com/y523172069-sudo/Personal-knowledge-base.git
```

进入知识库：

```powershell
cd Personal-knowledge-base
```

检查状态：

```powershell
git status
```

如果显示 `working tree clean`，说明同步正常。

## 3. 日常从云端拉取最新版本

每次在另一台电脑继续工作前，先拉取云端最新版本：

```powershell
git pull
```

建议习惯：

1. 开始工作前先 `git pull`；
2. 修改知识库；
3. 结束工作后提交并 `git push`。

## 4. 日常提交并推送

查看改动：

```powershell
git status
```

暂存改动：

```powershell
git add -A
```

提交：

```powershell
git commit -m "你的提交说明"
```

推送到 GitHub：

```powershell
git push
```

示例提交说明：

```powershell
git commit -m "chore: update weekly knowledge base notes"
git commit -m "docs: add ai risk assistant rotation notes"
git commit -m "feat: update internal demo view"
```

## 5. 换电脑工作时的推荐流程

### 电脑 A 工作结束

```powershell
git status
git add -A
git commit -m "chore: update knowledge base"
git push
```

### 电脑 B 开始工作

```powershell
git pull
```

如果两台电脑都改了同一个文件，可能出现冲突。遇到冲突时不要乱删内容，先停止操作，让 Codex 帮忙处理冲突。

## 6. 安全检查命令

推送前建议检查是否有不该提交的原始文件。

检查当前状态：

```powershell
git status --short
```

检查 Git 当前跟踪的 Office、图片、压缩包等文件：

```powershell
git ls-files | Select-String -Pattern "\.(xlsx|xls|docx|pptx|png|jpg|jpeg|zip|pdf|xmind)$"
```

如果没有输出，说明 Git 当前没有跟踪这些原始二进制材料。

检查忽略规则是否生效：

```powershell
git check-ignore -v "04-能力证据/原始材料-仅本地/任意文件名"
git check-ignore -v "01-收集箱/待整理原始材料/任意文件名"
```

## 7. 原始材料如何跨电脑同步

原始材料不建议直接放进 GitHub。

如果确实需要跨电脑同步，建议使用以下方式之一：

| 方案 | 适合场景 | 注意事项 |
| --- | --- | --- |
| OneDrive / 坚果云 / 百度网盘 | 简单备份原始材料 | 建议先加密，不要裸传内部材料 |
| Cryptomator 加密保险箱 | 云盘同步敏感文件 | 先加密，再同步 |
| VeraCrypt 加密容器 | 本地和移动硬盘同步 | 使用门槛略高 |
| Syncthing | 两台电脑点对点同步 | 不经过第三方云端，但需要配置设备 |

推荐做法：

```text
GitHub 私有仓库：同步知识库主体
加密云盘 / 点对点同步：同步原始材料
```

## 9. 遇到问题时怎么处理

| 问题 | 处理方式 |
| --- | --- |
| `git pull` 报冲突 | 不要随意覆盖，交给 Codex 合并 |
| `git push` 失败 | 先运行 `git pull`，再看是否有冲突 |
| GitHub 要求登录 | 使用 GitHub 登录窗口或 Personal Access Token |
| 误把敏感文件加入 Git | 先不要 push，立刻让 Codex 检查并移出暂存区 |
| 不确定能不能公开 | 默认不提交，只放入 `原始材料-仅本地` |

## 10. 最重要的规则

> 先拉取，再修改；先检查，再提交；原始材料不进 Git；不确定就先不 push。
