# 知识库治理规则

状态：生效中  
版本：1.4  
生效日期：2026-06-24  
适用范围：本知识库的目录、文档、模板、索引和本地原始材料

## 1. 治理目标

本规则用于保证知识库可查找、可维护、可验证，并避免在整理和对外转化过程中泄露敏感信息。

执行时遵循以下原则：

1. 先检查现有规则、链接和受影响范围，再进行结构性变更。
2. 优先增量修改，保持现有路径和链接兼容。
3. 未经明确要求，不批量改写、移动或重命名已有知识内容。
4. 事实、判断和对外表达分层保存，避免将未经验证的结论当作证据。
5. `.gitignore` 不是保密边界；是否可对外使用以文档的保密级别和人工复核为准。

## 2. 规则优先级

出现冲突时，按以下顺序执行：

1. 用户在当前任务中的明确要求；
2. 本治理规则；
3. 根目录 `README.md` 和知识库地图；
4. 各模块 `README.md`；
5. 模板中的默认字段和提示。

低层规则不得放宽高层规则中的保密、安全和兼容性要求。

## 3. 信息架构

| 区域 | 职责 | 不应存放 |
| --- | --- | --- |
| `00-导航` | 全局入口、治理规则、跨模块导航 | 具体项目正文和原始材料 |
| `01-收集箱` | 低成本捕获、待整理事项 | 已稳定沉淀的长期知识 |
| `02-管培生学习` | 岗位、业务和工作方法 | 单次项目的完整复盘 |
| `03-实践复盘` | 真实任务、项目过程和复盘 | 未核实的简历表述 |
| `04-能力证据` | 能力地图、证据索引和材料校验 | 未标明限制的对外宣传内容 |
| `05-求职资产` | 简历、述职、面试和 Demo 素材 | 未脱敏的内部原始材料 |
| `06-模板` | 统一记录结构 | 具体业务内容 |
| `07-访谈` | 背景、阶段和专题访谈 | 替代正式案例或证据索引 |

跨模块内容采用“一个主文档、多处引用”：完整事实保存在最合适的主文档中，其他模块只写摘要并使用相对链接引用，避免复制后产生多个版本。

## 4. 内容生命周期

默认流转路径为：

```text
收集箱 → 学习笔记 / 实践复盘 → 能力证据 → 求职资产
```

文档状态统一使用：

- `草稿`：结构或关键信息尚未补齐；
- `进行中`：正在持续补充或等待结果；
- `待验证`：已有判断，但缺少材料、数据或外部反馈；
- `已完成`：当前目的已满足，后续仅按需更新；
- `已归档`：不再作为当前入口，但因历史或引用关系保留。

不因状态变化修改文件名。归档内容默认保留原路径并在正文顶部标记状态；如确需移动，必须先检查并更新全部入站链接。

## 5. 命名规范

1. 顶层目录继续使用 `两位数字-中文名称`，未经整体架构评审不新增或调整编号。
2. 文件名使用能够直接表达主题的中文短语；英文缩写保留通用大小写，如 `AI`、`Jira`、`Demo`。
3. 文件名中避免空格和特殊字符 `<>:"/\|?*`；需要分隔两个语义段时使用半角连字符 `-`。
4. 不在文件名中加入“最终版”“最新版”等易失效状态；状态写在正文元数据中。
5. 连续访谈、阶段记录等确有顺序的内容可使用两位数字前缀，如 `00-启动访谈.md`。
6. 文件夹说明统一命名为 `README.md`。
7. 现有文件名保持兼容，不因本规则批量重命名；后续编辑时也不强制迁移，除非名称已造成误导或冲突。

## 6. 文档基础元数据

新建的学习笔记、实践复盘、能力证据和求职资产，应在一级标题后按需要记录：

```text
状态：草稿 / 进行中 / 待验证 / 已完成 / 已归档
创建日期：YYYY-MM-DD
更新日期：YYYY-MM-DD
保密级别：公开 / 已脱敏 / 仅本地
来源或证据：相对链接或简短说明
```

规则如下：

- `状态`、`更新日期`、`保密级别`为工作相关文档的必填项；
- 没有可靠来源时明确写“待补”，不得伪造引用；
- 修改事实、结论、状态或对外边界时更新日期；只修正错别字时可不更新；
- 现有文档采用“触碰即补齐”：只有在后续实质编辑时补充元数据，不集中迁移。

## 7. 链接与导航

1. 知识库内部统一使用相对链接，不使用本机绝对路径。
2. 知识库地图、根目录 `README.md` 等高频入口在 Codex 兼容模式下使用“名称 + `路径：...`”的纯文本路径，不使用 Markdown 可点击链接；普通正文文档不批量迁移，后续遇到同类闪退时按需转换。
3. 如需点击式导航，使用 `00-导航/知识库入口.html` 作为便捷入口；该 HTML 可以提供可点击链接、搜索和复制路径，但不得替代 `知识库地图.md` 的安全入口职责。
4. 新增重要文档后，至少从知识库地图、模块 `README.md` 或相关主文档获得一个入口。
5. 重命名或移动前，必须检查入站链接；变更后必须执行一次本地链接检查。
6. 链接到仅本地材料时，应在链接文字或同一行标注“仅本地”。
7. 对外导出内容不得依赖仅本地链接，必要时改为脱敏摘要或公开材料。

## 8. 保密与公开边界

保密级别定义如下：

- `公开`：已确认可以直接分享；
- `已脱敏`：仅可分享当前脱敏版本，原始材料仍不可公开；
- `仅本地`：不得上传、外发或复制到公开材料。

以下内容默认不得标记为公开：

- 员工、客户或联系人姓名及联系方式；
- 公司内部工单号、规则、流程和未公开产品信息；
- 原始业务数据、客户查询、会议原文和内部评价；
- 可反推出公司、客户或个人身份的文件名和组合信息。

本地原始材料只能存放在已明确标记并被忽略的目录中。索引可以记录材料存在，但可共享的 Markdown 中应优先使用匿名编号和概括性名称。

## 9. 模板管理

1. 通用结构由 `06-模板` 维护，新增同类文档优先复制对应模板。
2. 模板字段可以按实际情况扩展，但不得删除保密级别、责任边界、结果证据等关键约束。
3. 修改模板只影响后续新文档；已有文档不自动重写。
4. 模板发生不兼容变化时，应提升本规则版本并写明迁移方式。

## 10. 结构性变更流程

涉及目录、模板、命名、索引或跨模块约定的变更，按以下流程执行：

1. 检查现有规则、目录、链接和敏感信息范围；
2. 明确主文档、引用方和需要保持的旧路径；
3. 采用最小范围修改，避免顺手整理无关内容；
4. 验证链接、导航入口、模板字段和本地材料边界；
5. 完成后说明修改内容、影响范围、迁移事项和后续建议。

未经明确授权，不执行批量重命名、批量移动、批量内容改写或敏感材料外发。

## 11. 定期检查

### 每周

- 清理收集箱；
- 更新进行中的实践复盘；
- 检查新增重要文档是否有导航入口。

### 每月

- 更新能力地图和求职资产；
- 检查待验证结论和过期状态；
- 抽查敏感信息、仅本地链接和原始材料边界；
- 检查是否存在失效链接或重复主文档。

### 结构变更后

- 检查所有本地 Markdown 链接；
- 检查知识库地图和相关模块入口；
- 检查 `.gitignore` 与仅本地目录是否一致；
- 如有材料校验清单，重新验证文件大小和 SHA-256。

## 12. 材料请求与上传入口规则

当后续维护、复盘、简历蒸馏或证据补强需要新材料时，默认先执行本地检索，再请求用户上传。

执行顺序：

1. 先在当前知识库中检索，包括 `01-收集箱`、`03-实践复盘`、`04-能力证据/原始材料-仅本地`、`05-求职资产` 和已被 `.gitignore` 忽略的原始材料目录；
2. 再按上下文检索已知本地材料位置，例如桌面、产品部门轮岗材料文件夹、已出现过的截图和上传入口线程中列出的路径；
3. 输出“本地已找到材料”和“仍缺材料”；
4. 只有本地找不到或材料明显不完整时，再要求用户上传；
5. 要求上传时，优先指向 `自动化文件上传入口` 线程，线程 id：`019ef8d6-407f-7dd3-8887-48fb3014c7dd`；
6. 用户上传后，仍需先识别文件类型、主要内容和保密级别，再决定是否归档、复盘、写入证据或转化为简历素材。

不得因为缺材料就直接让用户重复上传；必须先说明已经检索过哪些位置、找到什么、缺什么。
