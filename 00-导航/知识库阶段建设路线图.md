# 知识库阶段建设路线图

创建日期：2026-06-26
状态：进行中
用途：定义个人知识库从“材料收集”到“简历 / Demo / 述职成品”的阶段性建设路径，并判断当前所处阶段。

## 1. 阶段总览

| 阶段 | 名称 | 核心目标 | 主要产物 | 当前状态 |
| --- | --- | --- | --- | --- |
| 0 | 基础设施搭建 | 先建立目录、规则、模板和保密边界 | 目录结构、治理规则、模板、`.gitignore` | 已完成 |
| 1 | 原始材料收集 | 把任务表、周报、截图、交付物、访谈记录先保存下来 | 收集箱、原始材料本地归档、校验清单 | 已完成主框架，持续进行 |
| 2 | 学习与实践结构化 | 把零散经历拆成学习笔记和实践复盘 | 管培生学习笔记、轮岗周报、项目复盘 | 已完成 3-6 月主线，7-8 月待继续 |
| 3 | 能力证据化 | 将复盘内容映射到能力、证据、限制和待补项 | 能力地图、证据索引、待补证据清单 | 已建立，持续补强 |
| 4 | 资产转化与原型化 | 把证据转成简历素材、述职主线和 Demo 初版 | 简历素材池、Demo 选题池、HTML Demo 两个版本 | 当前阶段 |
| 5 | 成品化交付 | 形成可直接使用的简历、Demo、讲解稿和述职材料 | 简历 V1、Demo V1、3-5 分钟讲解稿、述职稿 | 未完成 |
| 6 | 持续运营与版本维护 | 固定节奏维护知识库和对外资产 | 周维护、月度复盘、版本提交、保密检查 | 已启动，需长期执行 |

## 2. 每个阶段的进入与完成标准

### 阶段 0：基础设施搭建

进入条件：开始系统化整理个人知识库。
完成标准：

- 有稳定目录结构；
- 有治理规则；
- 有模板；
- 有本地原始材料保密目录；
- 有基础导航入口。

当前判断：已完成。

### 阶段 1：原始材料收集

进入条件：开始把工作材料集中放入知识库。
完成标准：

- 任务表、周报、工作日志、交付物、截图、会议纪要等能被归档；
- 原始材料进入仅本地目录或收集箱；
- 关键原始材料有校验记录；
- 不直接把内部材料写进简历或 Demo。

当前判断：主框架已完成，但该阶段会持续存在。后续 7-8 月轮岗材料仍需要继续进入该流程。

### 阶段 2：学习与实践结构化

进入条件：收集到的材料开始被整理成笔记和复盘。
完成标准：

- 每个重要轮岗阶段有学习笔记；
- 每个重要项目有实践复盘；
- 能区分“事实记录”和“个人理解”；
- 能从任务中提炼学习点、问题意识和下一步思考。

当前判断：3-6 月已经完成较多结构化沉淀，研发部门和金融产品与增值服务部门仍待后续补齐。

### 阶段 3：能力证据化

进入条件：复盘内容不再只是故事，而是开始映射到能力。
完成标准：

- 有能力地图；
- 有证据索引；
- 有待补证据清单；
- 每条能力尽量对应真实材料；
- 明确哪些内容可公开、哪些只能脱敏、哪些不得公开。

当前判断：已建立能力地图、证据索引和待补证据清单，但证据闭环仍在补强中。

### 阶段 4：资产转化与原型化

进入条件：已有足够案例，可以转成求职、述职或演示资产。
完成标准：

- 有简历素材池；
- 有 Demo 选题池；
- 有述职主线初稿；
- 有至少一个可打开的 Demo 原型；
- 对内版本和求职版本有边界区分。

当前判断：当前正处于该阶段。已经有简历素材池、Demo 选题池、述职主线初稿、HTML Demo 求职版和内部汇报版；但还没有完成最终简历 V1、正式讲解稿和成品化交付包。

### 阶段 5：成品化交付

进入条件：简历、Demo、述职主线都有原型。
完成标准：

- 简历 V1 可直接投递或用于定岗申请；
- Demo V1 可稳定演示；
- 有 3-5 分钟讲解稿；
- 有 3 个以上可追问项目案例；
- 已完成敏感信息检查；
- 领导版、求职版、个人维护版边界清楚。

当前判断：尚未进入。需要先完成阶段 4 的资产收束。

### 阶段 6：持续运营与版本维护

进入条件：知识库不再只是一次性整理，而是进入周期维护。
完成标准：

- 每周固定维护新增材料；
- 每月更新能力地图和求职资产；
- 每次关键变更有 git 提交；
- Demo 和简历随轮岗进展持续迭代；
- 保密边界持续检查。

当前判断：已启动，但还不是稳定成熟状态。

## 3. 当前阶段判断

当前知识库处于：

> 阶段 4：资产转化与原型化

判断依据：

1. 基础设施已经搭建完成：已有目录结构、治理规则、模板、导航入口和 `.gitignore`。
2. 3-6 月主要学习内容已经结构化：已有管培生学习笔记、轮岗周报归档和多个项目复盘。
3. 能力证据体系已建立：已有能力地图、证据索引、待补证据清单和原始材料校验清单。
4. 求职资产已经开始转化：已有简历素材池、Demo 选题池、定岗定位初稿、岗位方向分析和述职报告主线初稿。
5. Demo 已经进入原型阶段：已有个人知识库 HTML Demo，并拆分为求职版和内部汇报版。
6. 但成品尚未完成：最终简历 V1、正式 Demo V1、讲解稿和 8 月底交付包仍未完成。

所以当前不是“从零建设阶段”，也不是“最终交付阶段”，而是从知识库沉淀向可展示资产转化的中段。

## 4. 当前阶段的优先任务

阶段 4 期间不应继续无限扩展材料范围，而应优先完成以下动作：

1. 收束主线：确定最终要服务“定岗申请、述职、求职 Demo”三类用途中的优先级。
2. 梳理 3 个主案例：小联盟资质认证调研、Jira 产品优化需求、AI / 会员产品调研中选择主线。
3. 明确版本边界：求职版、领导汇报版、后台维护版分别维护，不混用表达。
4. 抽取简历 V1：从简历素材池中先生成一版 1 页简历草稿。
5. 准备讲解稿：围绕 Demo 和 3 个案例形成 3-5 分钟讲解稿。
6. 继续接入 7-8 月材料：研发部门和金融产品与增值服务部门材料进入收集箱后，再按阶段 2-4 流程沉淀。

## 5. 阶段 4 进入阶段 5 的条件

当以下内容完成后，可以判断进入阶段 5：

- 简历 V1 已形成；
- Demo V1 已确定演示路径；
- 领导版和求职版口径稳定；
- 3 个项目案例可讲清楚背景、行动、收获、限制；
- 敏感信息检查通过；
- 3-5 分钟讲解稿初版完成。

## 6. 每周维护时的阶段检查问题

每周维护时先问这 5 个问题：

1. 本周新增材料属于哪个阶段：收集、结构化、证据化，还是资产转化？
2. 有没有新材料能增强当前 3 个主案例？
3. 有没有内容应该只留在后台，不进入简历或 Demo？
4. 当前简历、述职、Demo 哪一个最需要更新？
5. 当前是否已经满足进入阶段 5 的条件？
