## 《人人都是产品经理》读书笔记

### 产品经理思考逻辑

1. 做这件事的目的是什么？
2. 客户的需求是什么？
3. 产品经理在团队中的定位是：要做什么，来解决什么人的什么需求。

### 产品的关键词与分类

- 产品是解决某个问题的东西。
- 用户、需求、了解，共同描述“什么问题”。
- “东西”对应解决方案。

产品六大类：

1. 工具
2. 内容
3. 社交
4. 交易
5. 平台
6. 游戏

### 需求采集与功能管理

一个功能的 DNA：

1. 基础功能
2. 亮点功能
3. 期望功能
4. 无差别功能
5. 反向功能

后续要做：

- 功能打包。
- 确定 MVP。
- 管理需求与功能。

常见文档：

- MRD：市场需求文档。
- PRD：产品需求文档。

### 产品研发环节

```text
立项 → 需求 → 开发 → 测试 → 发布
```

### 产品经理问题清单

- 为什么要做这个？不做行不行？
- 这是用户的目标，还是我们的目标？
- 用户有普遍性吗？能代表多少人？对我们的优先级是多少？
- 数据来源是什么？什么时候获取？如何采样？
- 产品线大图是什么？五年后是什么样子？
- 如何实现？如果只做一件事，最重要的是什么？
- 能给出量化指标吗？ROI 是多少？
- 团队多少人？如何分工？
- 实现路上最大的问题是什么？打算如何解决？

### 产品生命周期

- 验证期
- 爆发期
- 平台期
- 衰退期

## 产品经理学习日记

### 产品经理需要做什么

把模糊的想法，翻译成清晰、可执行、有边界的需求。

### 学习工具

- 廖雪峰教程：`http://liaoxuefeng.com/index.html`
- 人人都是产品经理：`https://www.woshipm.com/`

### 用 AI 梳理 PRD 的提示词模板

```text
你是一位资深产品经理。我有一个还很模糊的产品想法：
［一句话描述你的想法］
请用苏格拉底式追问帮我厘清它。规则：
1. 一次只问我一个问题，绝不一次甩出多个。
2. 根据我的回答，决定下一个问题——像剥洋葱，一层一层往下挖。
3. 重点覆盖：给谁用、解决什么具体痛点、只做一个核心功能是哪个、
什么算成功（可衡量）、明确不做什么。
4. 当你判断信息已经足够，主动停下，输出一份结构化 PRD，包含：
项目定位 / 目标用户与场景 / 核心痛点 / MVP 核心功能（只列 1 个）/ 成功标准 / 明确不做的事。
5. 全程不写代码、不画原型，只追问与梳理。
现在，从你的第一个问题开始。
```

## 初步沉淀

1. 产品经理的核心不是写文档，而是把模糊问题变成有边界、可执行、可验证的方案。
2. 判断需求时，要持续区分用户目标、业务目标和团队目标。
3. MVP 的重点是只保留最关键的核心功能，并明确不做什么。
4. AI 可以作为产品需求澄清工具，但前提是提示词能强制单点追问、逐层下钻。
