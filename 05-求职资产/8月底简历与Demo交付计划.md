# 8月底简历与 Demo 交付计划

状态：初稿  
创建日期：2026-06-25  
目标截止：2026-08-31

## 1. 总目标

在管培生轮岗结束前，形成一套可用于定岗申请、述职和后续求职展示的成品材料：

1. 一份定岗 / 求职简历 V1；
2. 一个可打开、可演示、可讲解的 Demo；
3. 一套 3-5 分钟项目讲解稿 / 述职素材。

主线暂定为：

> 我在跨部门轮岗中，逐步建立了从客户问题、业务需求到产品方案和项目推进的落地能力。

## 2. 最终交付物

| 交付物 | 目标形态 | 用途 | 验收标准 |
| --- | --- | --- | --- |
| 简历 V1 | 1 页中文简历，可按岗位微调 | 定岗申请、求职投递 | 至少包含 3 条有证据支撑的项目经历，不强写未验证成果 |
| Demo V1 | 本地可运行或静态可打开的演示项目 | 面试 / 述职展示能力闭环 | 有清晰用户、痛点、核心页面、示例数据和讲解路径 |
| Demo 讲解稿 | 3-5 分钟口径 | 面试时讲清楚为什么做、怎么做、价值是什么 | 能说清背景、方案、取舍、结果和下一步 |
| 项目案例库 | 3-4 个结构化案例 | 支撑简历和面试追问 | 每个案例包含背景、目标、行动、结果、证据和限制 |
| 保密版资产包 | 脱敏后的截图、数据、文案 | 对外展示 | 不包含客户、员工、内部工单号、公司敏感规则和原始数据 |

## 3. Demo 选题决策

首选 Demo：

> 管培生成长证据库

选择理由：

- 直接服务定岗、述职和求职，不是为了做 Demo 而做 Demo；
- 数据主要来自个人知识库，保密风险最低；
- 能展示产品设计、信息架构、项目推进、复盘和求职转化能力；
- 与当前能力定位一致：把零散工作经历转化为可验证的项目成果。

暂不优先做：

- AI 产品使用分析看板：数据敏感，适合后续用合成数据做补充；
- 企业服务能力认证工具：业务特色强，但需要重建公开规则，成本较高；
- 课程试点运营台：适合作为会议 / 产品运营方向的补充案例，不作为主 Demo。

## 4. Demo V1 页面范围

Demo V1 先控制在 5 个核心页面，避免范围过大：

| 页面 | 解决的问题 | 核心内容 |
| --- | --- | --- |
| 首页总览 | 一眼看清管培成长主线 | 轮岗时间线、关键项目、能力标签、证据完整度 |
| 项目案例 | 把工作经历变成可讲案例 | 小联盟调研、Jira 需求、AI 使用分析、云课堂复盘 |
| 能力地图 | 展示能力不是自我评价，而是有证据支撑 | 项目推进、调研、产品方案、数据分析、客户沟通、汇报表达 |
| 证据索引 | 说明每条成果的证明材料和限制 | 原始材料类型、可公开程度、缺口、脱敏规则 |
| 简历 / 述职导出 | 把知识库转成求职资产 | 简历 bullet、面试讲法、述职主线 |

V1 不做复杂登录、数据库、多用户协作和真实公司系统复刻。

## 5. 简历素材优先级

| 优先级 | 素材 | 简历使用方式 | 当前限制 |
| --- | --- | --- | --- |
| P0 | 小联盟资质认证调研 | 可作为独立项目经历 | 最终上线与指标未知，不能写成已上线成果 |
| P0 | 3 项 Jira 产品优化需求 | 可作为产品需求 / 项目推进经历 | 不公开工单号，需等验收或上线补强 |
| P0 | AI 风控官内部使用分析 | 可作为数据分析 + AI 产品调研经历 | 必须脱敏，优先使用区间或合成数据 |
| P1 | 商学院云课堂课题 | 更适合面试复盘和述职中的学习案例 | 方案未落地，不作为主成果 |
| P2 | 基础轮岗任务 | 作为背景，不单独包装成果 | 证据和结果不足 |

## 7. 每周维护动作

每周维护时按这个顺序处理：

1. 清理收集箱：把新增任务、截图、会议纪要、交付物归档；
2. 更新实践复盘：至少补一件本周重要工作；
3. 更新证据索引：新增材料、状态变化、限制条件；
4. 更新简历素材池：只写有结果或有明确过程价值的内容；
5. 更新 Demo：把最新案例或状态同步到页面结构；
6. 记录待补项：不要为了完整而编造结果。

## 8. 保密边界

公开简历和 Demo 中不得出现：

- 客户名称、员工姓名、内部账号；
- 公司内部工单号；
- 具体风控规则、审核规则、赔付规则；
- 原始聊天记录、客户查询、会议纪要全文；
- 未经允许披露的业务数据。

可使用：

- 脱敏后的问题类型；
- 汇总后的区间数据；
- 个人负责的工作方法；
- 抽象后的流程和页面结构；
- 合成数据与模拟案例。
