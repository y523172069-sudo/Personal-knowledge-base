# 个人知识库工作流说明

- 状态：进行中
- 创建日期：2026-07-19
- 更新日期：2026-07-19
- 保密级别：已脱敏
- 定位：个人工作流说明 / 汇报与求职候选资产
- 证据属性：本文件用于说明知识库的设计与使用方式，不直接作为个人能力证据；涉及能力认定时仍需回到项目复盘和证据索引核验

## 1. 文档目的

本文档用于说明我为什么建设个人知识库、知识库采用什么框架、日常如何与它交互，以及它如何将工作中的零散材料逐步转化为学习沉淀、实践复盘、能力证据和展示资产。

这份文档可以用于：

- 向领导说明我如何整理轮岗学习和阶段成长；
- 向 HR 或用人部门展示我的个人工作方式；
- 作为个人知识库 Demo 的项目说明；
- 作为后续优化知识管理流程的基线文档。

## 2. 一句话定义

我的个人知识库不是单纯的资料文件夹，而是一套以真实工作为输入、以学习和复盘为加工过程、以证据为审核层、以简历、述职和 Demo 为输出的个人成长工作流。

```text
真实工作材料
→ 收集与分类
→ 学习笔记 / 实践复盘
→ 能力证据与限制核验
→ 简历 / 述职 / 面试案例 / Demo
```

## 3. 为什么建设这套知识库

管培生轮岗涉及多个部门和不同类型的工作，材料分散在任务表、周报、PPT、Excel、会议纪要、截图和即时沟通中。如果只保留文件，容易出现以下问题：

1. 做过很多事情，但无法快速说明自己具体做了什么；
2. 学习内容停留在零散笔记，难以形成可复用的方法；
3. 项目经历与个人能力之间缺少明确证据链；
4. 准备述职、定岗或求职时，需要重新翻找和回忆；
5. 内部材料、个人理解和对外表达容易混在一起；
6. 没有一个持续展示个人成长、工作方式和项目积累的载体。

因此，我希望通过知识库建立一条稳定链路：工作发生时先留下材料，阶段结束后完成复盘，证据充分后再形成可用于汇报或求职的资产。

## 5. 内容如何流转

### 5.1 第一层：记录真实材料

输入包括：

- 工作日志、任务表和周报；
- Excel、Word、PPT、需求文档和思维导图；
- 需求评审、开发、验收和状态截图；
- 会议纪要、业务访谈和客户反馈；
- 主管、同事或业务方的具体评价；
- 排名、评分、数量和其他可核验结果；
- 新学到的方法、工具和失败复盘。

新材料首先进入收集箱或仅本地原始材料目录。此时只确认“材料是什么”，不立即判断它能证明什么能力。

### 5.2 第二层：区分学习与实践

同一项工作可能产生两种内容：

- **学习笔记**：我理解了什么业务、岗位、流程或方法；
- **实践复盘**：我在一个真实任务中承担了什么角色、采取了什么行动、产生了什么结果。

学习笔记负责形成可复用认知，实践复盘负责保留真实场景和个人行动，两者通过链接关联，但不重复保存完整正文。

### 5.3 第三层：建立能力证据

实践复盘完成后，再检查：

1. 项目或任务是否真实明确；
2. 我的职责和团队职责是否区分清楚；
3. 是否存在交付物、反馈、数据或状态记录；
4. 结果能够证明到什么程度；
5. 有哪些限制和仍缺材料；
6. 是否已经建立证据编号 `E-XXX`；
7. 是否允许进一步转成对外表达。

证据不足时，内容只保留在复盘或待补证据清单，不为了增加简历内容而强行包装成成果。

### 5.4 第四层：转化为不同资产

证据充分后，根据使用对象转成不同版本：

| 版本 | 使用对象 | 表达重点 |
| --- | --- | --- |
| 后台维护版 | 自己和知识库维护过程 | 原始事实、证据、限制、缺口、待确认事项 |
| 内部汇报版 | 公司领导和同事 | 学习、共创、成长、阶段思考和工作投入 |
| 求职版 | HR 和用人部门 | 问题、个人行动、能力、结果和贡献边界 |
| Demo 版 | 领导、面试官或作品集读者 | 真实问题、信息架构、解决链路和交互呈现 |

不同版本不直接复制内部原始材料。涉及公司、客户、内部数据和流程的信息，需要使用脱敏摘要、公开资料或合成数据。

## 6. 我如何与知识库交互

我主要通过自然语言与 Codex 交互，不需要自己记住所有文件位置和维护步骤。

| 我的输入 | 知识库执行动作 | 典型输出 |
| --- | --- | --- |
| “这是本周的周报” | 识别新事件、项目、学习和材料线索 | 周报归档、项目补充、待整理事项 |
| “同步一下这条线索” | 先记录事实并查找对应主文档 | 收集箱记录或项目阶段更新 |
| “开始每周维护” | 搜索本地材料并沿沉淀链路更新 | 每周维护记录、证据和资产更新 |
| “还需要什么材料” | 先搜索知识库和已知本地路径 | 已找到材料、仍缺材料、上传提醒 |
| “这个项目能不能写进简历” | 核对复盘、E 编号、贡献边界和结果限制 | 可用口径、不可用口径和待补证据 |
| “更新领导版 Demo” | 使用内部汇报口径维护页面 | 学习、共创、成长和阶段思考 |
| “更新求职版 Demo” | 使用脱敏后的求职口径维护页面 | 简历入口、案例详情和项目说明 |
| “同步到云端” | 检查敏感文件、提交版本并推送 | Git 提交、分支或 Draft PR |

如果需要补充材料，系统默认先搜索当前知识库、仅本地材料目录和已经出现过的本地路径；只有本地未找到时，才要求我重新上传。

## 7. 人与 AI 的协作边界

这套知识库不是由 AI 自动决定个人能力，而是由我提供事实、确认边界和作出关键判断，AI 协助完成信息处理和维护。

### 我的职责

- 明确知识库要服务的目标；
- 提供真实工作材料和背景；
- 确认哪些行动属于个人贡献；
- 判断事实、口径和能力表述是否准确；
- 决定哪些内容可以用于内部汇报或外部求职；
- 对最终输出承担确认责任。

### AI / Codex 的职责

- 搜索和读取已有本地材料；
- 将零散材料结构化整理；
- 根据模板生成笔记、复盘和索引草稿；
- 检查链接、文件范围、证据缺口和保密风险；
- 协助维护 HTML Demo 和版本记录；
- 在需要判断时提供当前口径、候选口径、差异和影响。

### 决策规则

- 明确且可逆的流程节点，自动采用推荐方案；
- 涉及事实认定、能力判断、表达口径或使用范围时，由我确认；
- 不将团队成果全部归因于个人；
- 不将“提供依据”改写成“独立落地”；
- 不将“通过审核”改写成“已上线”；
- 不虚构收入、增长、效率、准确率、采纳或业务结果。

## 8. 固定维护节奏

### 日常捕获

新任务、新材料和新想法先进入收集箱，不要求当场完成完整复盘。

### 每周维护

1. 搜索本周新增材料；
2. 输出已找到材料和仍缺材料；
3. 清理收集箱；
4. 选择重要工作完成或更新实践复盘；
5. 更新证据索引、能力地图和待补证据清单；
6. 证据充分时再更新简历、述职和 Demo；
7. 记录本周新增、更新、待补和保密提醒。

### 每月检查

- 更新能力地图和求职资产；
- 检查待验证结论和过期状态；
- 检查敏感信息和仅本地材料边界；
- 检查失效链接、重复文档和缺失导航入口。

### 关键版本维护

知识库主体通过私有 GitHub 仓库在不同电脑之间同步。Markdown、脱敏复盘、索引和 Demo 源文件可以同步；公司原始 Excel、Word、PPT、截图、客户信息和内部数据只保存在本地。

详见：[云端同步使用说明](../00-导航/云端同步使用说明.md)。

## 10. 可用于汇报的表达

> 我在轮岗过程中发现，任务表、周报、PPT和项目文件虽然记录了我做过什么，但很难直接回答“我学到了什么、形成了什么能力、哪些经历可以被验证”。因此，我借助 AI 建立了一套个人知识库工作流：先收集真实材料，再将其拆分为学习笔记和项目复盘，通过证据索引确认个人贡献和结果边界，最后转化为述职、简历和 Demo。这个知识库既是轮岗学习档案，也是我持续复盘和管理个人成长的基础设施。

## 11. 可用于求职或面试的表达

> 我把个人知识库当成一个长期产品来建设。它解决的不是“文件放在哪里”，而是“零散工作经历如何变成可验证、可复用、可展示的个人资产”。我负责定义目标、提供材料、确认贡献边界和最终口径，使用 AI 协助完成材料搜索、结构化整理、证据检查、文档维护和静态 Demo 原型。整个系统包含收集、学习、复盘、证据和展示五个环节，并通过 Git 进行版本管理。对外展示时只使用脱敏摘要和合成数据。

这段表达用于介绍项目工作方式，不自动等同于“独立完成全栈产品”或其他能力结论。正式使用前，应根据目标岗位和实际 Demo 完成度调整措辞。

## 12. 后续迭代方向

1. 将 Markdown 内容与 HTML Demo 自动同步，减少重复维护；
2. 建立项目、证据、能力和对外素材之间的可视化关系；
3. 增加简历 bullet、述职摘要和案例讲解稿导出；
4. 进一步区分个人维护版、领导汇报版和公开求职版；
5. 根据后续轮岗和项目结果持续更新证据链；
6. 在成品稳定后形成公开部署版本和完整项目说明。

## 13. 总结

这套工作流的核心不是记录更多内容，而是让每一段重要经历都能够回答四个问题：

1. 我遇到了什么问题？
2. 我采取了什么行动？
3. 有什么材料能够证明？
4. 它可以如何转化为下一次工作的能力和资产？

一句话总结：

> 先把工作留下来，再把经历讲清楚；先用证据确认边界，再把沉淀转化为可展示的个人资产。
